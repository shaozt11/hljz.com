生态开发

围绕 云OS SDK 的接入规范、宿主桥接能力和后续扩展路线，整理为开发者可直接使用的入口。 当前重点是 Shell Bridge，后续按 SDK v2 逐步补齐存储、协同和原生 UI 能力。

SDK OVERVIEW

SDK 现状

v1 已提供桌面桥接层，v2 在此基础上扩展更完整的应用能力。

Shell Bridge v1

作为独立 SDK 模块接入，用于应用主动唤起宿主能力，例如打开系统应用、聚焦窗口、最小化、关闭和桌面通知。

SDK v2 规划

新增应用私有 result 目录、原生协同会话和宿主渲染的弹窗能力，目标是把“能力暴露”标准化，而不是把业务逻辑塞进 SDK。

INTEGRATION

接入要点

建议新应用先接入 v1，再按需扩展 v2。

1. 加载公共脚本

页面通过 `/sdk/roxet-bridge.js` 引入桥接脚本，作为应用和宿主之间的统一入口。

2. 注册桥接对象

调用 `window.Roxet.registerShellBridge()` 获取能力实例，再在业务事件中触发宿主动作。

3. 保持职责清晰

SDK 只负责能力暴露，不负责业务状态、复杂同步或内部 UI 改造。

API

典型接口

下面是文档中最核心的使用方式，适合直接写入开发页。

Shell Bridge v1 
<script src="/sdk/roxet-bridge.js"></script>
<script>
  const shell = window.Roxet?.registerShellBridge?.()

  shell?.notify("保存成功", "success")
  shell?.openApp("drive")
  shell?.focusWindow()
</script>
SDK v2 建议接口 
window.Roxet.storage.list()
window.Roxet.storage.read(path)
window.Roxet.sync.join({ appId: "draw", mode: "collab" })
window.Roxet.ui.alert({ title, message })
MANIFEST

能力声明

建议在 `manifest.json` 中显式声明应用使用到的 SDK 能力。

{
  "sdk": {
    "storage": true,
    "collaboration": true,
    "nativeDialog": true
  }
}

这类声明便于宿主按能力做权限、渲染和兼容性控制，也便于后续扩展新模块。

ROADMAP

推荐落地顺序

从最小可用功能开始，逐步扩展到更完整的生态开发能力。

  • 先完成 Shell Bridge 接入，让应用具备基础桌面交互能力。
  • 再补充 result 目录和云文件扫描，形成应用级持久化能力。
  • 最后引入协同会话和原生弹窗，提升复杂应用的交互一致性。
