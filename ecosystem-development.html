02 / DEVELOPMENT

生态开发

这是 RoxetOS / 云OS 的开发者接入页，按 SDK v2 的方式整理应用私有存储、协同会话、原生弹窗和宿主桥接能力。 目标很简单：让应用只通过 SDK 和宿主交互，不直接碰系统内部实现。

POSITIONING

开发定位

v1 解决桌面桥接，v2 补齐应用级持久化、协同和宿主原生 UI。

宿主负责什么

窗口管理、通知、原生弹窗、应用打开、云文件扫描和协同会话的统一调度。

应用负责什么

业务状态、页面渲染、操作流转，以及把可持久化内容写入自己的 `result/` 目录。

STRUCTURE

推荐目录结构

优先保持应用目录清晰，让宿主能稳定发现结果文件和静态资源。

sys/
└── notes/
    ├── manifest.json
    ├── app.py
    ├── templates/
    ├── static/
    └── result/

`result/` 是应用私有输出目录，宿主会扫描 `user/<username>/sys/*/result/**` 并在云文件中展示。

MANIFEST

能力声明

建议在 `manifest.json` 里显式声明应用用到的 SDK 能力。

最小配置 
{
  "id": "notes",
  "name": "Notes",
  "version": "1.0.0",
  "launch": "http://127.0.0.1:5000"
}
推荐配置 
{
  "id": "notes",
  "name": "Notes",
  "version": "1.0.0",
  "launch": "http://127.0.0.1:5000",
  "sdk": {
    "storage": true,
    "collaboration": true,
    "nativeDialog": true
  }
}
BOOTSTRAP

初始化 SDK

先引入桥接脚本，再按需获取能力实例。

桥接入口 
<script src="/sdk/roxet-bridge.js"></script>
<script>
  const shell = window.Roxet?.registerShellBridge?.()
</script>
能力入口 
window.Roxet.storage
window.Roxet.ui
window.Roxet.sync
window.Roxet.version
SHELL BRIDGE

宿主桥接能力

保留 v1 的核心能力，用于窗口和宿主动作控制。

通知

`shell.notify(message, type)` 用于成功、警告、错误和普通提示。

打开应用

`shell.openApp(appId)` 用于从当前应用跳转到系统应用。

窗口控制

`shell.focusWindow()`、`shell.minimizeWindow()`、`shell.closeWindow()` 负责基础窗口交互。

STORAGE

应用私有存储

应用只能默认写入自己的 `result/`，不能越界访问别的应用目录。

常用接口 
window.Roxet.storage.list()
window.Roxet.storage.read(path)
window.Roxet.storage.write(path, data)
window.Roxet.storage.remove(path)
window.Roxet.storage.pickFolder()
约束
  • 默认只允许写入本应用的 `result/`。
  • 云文件应用负责扫描和展示结果文件。
  • 这不是通用网盘，也不是跨应用共享存储。
UI + SYNC

原生弹窗与协同

复杂应用优先用宿主能力，避免自己在 iframe 里重造 UI 和同步层。

原生弹窗 
window.Roxet.ui.alert({ title, message })
window.Roxet.ui.confirm({ title, message })
window.Roxet.ui.prompt({ title, message, defaultValue })
window.Roxet.ui.custom({ title, content, actions })
协同会话 
const session = window.Roxet.sync.join({
  appId: "draw",
  mode: "collab"
})

适合画板、文档编辑器和需要实时同步状态的应用。

ROADMAP

推荐落地顺序

按最小可用能力逐步扩展，先稳定再增强。

  • 先接入 `Shell Bridge`，把通知、开窗和窗口控制跑通。
  • 再补 `result/` 和 `storage`，形成应用私有持久化。
  • 最后接入 `ui` 和 `sync`，完善复杂交互与实时协作。
CHECKLIST

发布前检查

上线前至少确认这些项没有问题。

  • `manifest.json` 能正确声明应用和 SDK 能力。
  • 应用可正常启动，窗口关闭和刷新后不会异常。
  • 读写文件、原生弹窗和协同会话都能按预期工作。
  • 不会访问未授权目录，也不会把控制台刷成错误输出。
