云OS
把桌面、云盘、系统应用和会话运行连成一体

这是 云OS 的工程版本展示页。当前目标不是堆叠功能列表，而是先把一个可用的 WebOS 外壳真正跑通： 用户登录后进入桌面，通过统一 API 管理云盘、系统应用、窗口和运行时。

React + Vite + TypeScript FastAPI + WebSocket SQLite + SessionMiddleware 系统应用沙箱 持久化会话
核心定位

先做一个能用的 WebOS 外壳

工程版本的重点是把真实运行链路补齐，而不是只做演示页。

统一入口

登录、注册、注销、桌面入口和系统应用入口都收束到同一套前端壳层中。

统一数据层

用户数据、云盘文件、系统应用状态和运行时都按目录和接口分层管理。

统一运行层

系统应用通过独立子进程和 WebSocket 运行，关闭窗口不等于停止程序。

架构图

工程结构

参考苹果官网的表达方式，这里把技术栈拆成几层，便于快速理解整体边界。

Interaction Layer

桌面、窗口和内置应用界面

负责登录页、桌面、任务栏、开始菜单、窗口管理、拖拽、托盘和内置应用 UI。

前端

React + Vite + TypeScript

HTTP API / WebSocket
Service Layer

FastAPI 后端

负责认证、云盘、系统应用扫描、应用运行、浏览器代理、静态资源和会话管理。

/api/auth/* /api/drive/* /api/apps /ws/apps/{appName}

用户数据 / 应用状态 / 运行时
Data Domain

数据与目录

  • data/roxetos.db
  • user/<username>/cloud/
  • user/<username>/sys/<app>/state.json
  • user/<username>/sys/<app>/runtime/
App Domain

系统应用发现

  • 优先找 main.py、app.py
  • 支持读取 manifest.json 和 logo
  • 前端会展示平台不兼容状态
  • 应用列表由后端扫描结果提供
Runtime Domain

系统应用运行时

  • 子进程启动与 stdin/stdout 管理
  • WebSocket 广播输出
  • 关闭窗口不等于停止后台进程
  • 再次打开可重新附加会话
工程能力

当前已经补齐的主链路

这些内容来自 v1 的实现说明和技术架构，适合直接展示为工程进展。

登录与会话

使用 SessionMiddleware 维持登录态，前端通过 /api/auth/me 恢复当前用户。

云盘

统一采用 /api/drive/*，覆盖文件列表、上传、预览、重命名、删除和下载。

系统应用

扫描 sys/ 下的应用目录，返回兼容性状态，并通过 /ws/apps/{appName} 运行。

浏览器代理

通过后端同源代理加载目标网站，降低 iframe 被阻止的概率。

接口与状态

版本边界

这里不是“还缺什么”，而是“当前已经到哪里”。

前端状态

桌面布局、窗口状态、应用列表和当前用户状态由前端 store 统一管理。

后端状态

用户、云盘、系统应用运行目录和持久化会话均有明确的数据落点。

兼容策略

不兼容的平台应用会保留在列表中，但打开后会显示不支持提示。

后续重点

继续统一旧新接口命名、补齐持久化策略和窗口边缘交互。
